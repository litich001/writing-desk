# 热点榜是怎么筛的

对外讲解用。每一句都能对上代码。

## 一句话

**热点榜只解决「今天有什么值得写」，不解决「你写什么」。**
榜单是把 15 个平台的公开热榜按标题归并、去重、排热度，让你别再一个个网站刷。
它给的是**选题入口**，不是选题。能不能写、写得值不值得，是你自己的判断。

---

## 一、数据从哪来

15 个源，分三类。**全部是公开可访问的页面或接口，不登录、不绕过任何反爬。**

| 类别 | 源 | 说明 |
|---|---|---|
| 综合热搜 | 百度热搜、微博热搜、头条热榜 | 覆盖面最广，全民话题 |
| 垂类 | B站热门、抖音热点、知乎日报、豆瓣小组、B站排行 | 年轻人、圈层在谈什么 |
| 财经科技 | 澎湃新闻、IT之家、掘金、量子位、InfoQ、新浪财经、东方财富、虎扑 | 有信息量的地方 |

**抓不到就标不可用，绝不拿假数据凑数。**
这是硬规矩：选题靠假榜是致命的。界面会直接告诉你哪几个平台抓不到，
而不是悄悄塞一堆编的条目进去。反爬的源（豆瓣 403、部分平台要 JS）就是抓不到，
我们不绕，只标出来让你手动去原站看。

## 二、跨平台去重：同一条新闻只算一条

同一个事件会被 5 个平台同时报，如果不去重，用户看到的榜单就是同一件事刷五遍。

**做法**：取标题清洗后的前 14 个字做键。

```
"国务院部署中秋国庆假期工作安排"  →  国务院部署中秋国庆假期
"国务院部署中秋国庆假期工作安排"  →  国务院部署中秋国庆假期   ← 同一条
```

清洗规则：去掉所有非中英文数字的字符（标点、空格、符号），再截前 14 字。

**为什么是 14 字**：足够长，能区分「国务院部署…」和「国务院批准…」；
又足够短，能容得下同一条新闻的不同媒体改写（「部署中秋国庆假期工作安排」vs
「国务院部署中秋国庆假期工作有关安排」前 14 字一样）。

**14 字以内的标题**直接用清洗后的全文做键。

去重之后，合并同一条的所有来源平台，界面上标成「3 源」。
**「3 源」本身就是选题信号** —— 三个平台同时在谈的话题，比只在角落出现的话题更值得写。

## 三、排序：热度 + 跨源数

同一条新闻的热度取各平台里的最大值（不是相加 —— 相加会让某平台刷榜的条目虚高）。
然后：

1. 按热度降序
2. 热度相同时，跨源多的排前面

**为什么不是加权打分**：任何权重都是在拍脑袋。
「热度 × 1.2 + 跨源 × 500」这种公式看起来精妙，实际效果不如直接排序 + 并列时看跨源，
而且没人能解释它。宁可简单到能对外讲清。

## 四、什么时候刷新

- **内存缓存 5 分钟**：同一次会话内翻页、切平台不重复打源站。
- **落盘缓存 4 小时**：进程重启也不丢，不会在你重启服务时把 15 个站点全打一遍。
  用户明确要求「每隔 4 小时自动刷新」，这就是那个 4 小时。
- **4 小时内的请求直接读盘**，不打网络。
- **抓取失败退回盘上的旧数据**，并打上「数据是旧的」标记。
  **宁可旧，不可空** —— 空榜会让用户以为今天没热点。
- 只有「至少一个源抓到成功」才刷新整盘的时效，防止一个源成功就把全盘的时间戳刷新了。

## 五、命令行怎么用（给任何 Agent）

```bash
node engine/hot-cli.mjs                    # 人看的表格
node engine/hot-cli.mjs --json             # 结构化
node engine/hot-cli.mjs --json --flat --top 30   # 最适合喂给模型
node engine/hot-cli.mjs --only weibo        # 只看一个平台
node engine/hot-cli.mjs --force             # 忽略 4 小时缓存，强制重抓
node engine/hot-cli.mjs --stale             # 过期也返回，附 stale 标记
```

**退出码有意义**：0 = 至少一个源出了条目；1 = 全军覆没。
调用方可以据此决定要不要重试，不会把「抓取失败」误当成「今天没热点」。

### 关于可移植性，说句实话

**不能吹「任何 Agent 即插即用」。**
榜单本质是 HTTP 抓取 + HTML 解析。不同 Agent 的网络出口、运行时、反爬处境差别很大，
A 环境能抓的源 B 环境不一定能抓。

能做到的是：

- 一个**纯 CLI**，不需要启动写作台的 server，不需要开浏览器
- 明确的**退出码**和 JSON 结构，调用方能自己判断
- `--stale` 让调用方在网络不通时也能拿到数据（而不是什么都没有）
- 15 个源里**有一部分是纯 JSON 接口**（百度、微博、头条），这类最稳；
  依赖 HTML 解析的源会随对方改版失效 —— 这是客观限制，不是 bug

## 六、热点页怎么用

1. **点条目** → 右边出细节
2. **点「看看原文讲了什么」** → 服务端代抓正文，在页面上直接读，不用跳走
   - 抓不到会明说抓不到（对方反爬或是 JS 壳页），并给「直接打开原页」的按钮
   - 不给你一堆站点导航当正文
3. **填切入角度**（选填）
4. **用这个题** → 带着角度进定题页
5. **存进我的选题** → 存起来慢慢想

平台切换和刷新按钮是**常驻的**，榜单很长，滚下去也不会找不到。

## 七、筛选逻辑一句话版（对外讲的时候这么说）

> 我们把 15 个平台的公开热榜拉下来，用标题前 14 个字归并去重，同一条新闻只留一条并标出它上了几个平台，然后按热度排序。
> 三个平台同时在谈的排前面 —— 那是真热点。只在一个平台角落出现的，可能是别人的日常。
>
> 但榜单只是入口。真正决定能不能写的，是你能给出别人没有的那个角度。
> 一条十个平台都在报的新闻，写好它需要的是别人写不出的那一句话；写不出那句话，就别写这条。
