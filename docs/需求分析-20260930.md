## 0. 先说三个判断错在哪

用户说"之前可以控制字的大小颜色，现在没了"——**这是误解，但误解得有道理**。

实测：字号/颜色的数据一直都在 `layout.mjs` 的 `preview: { fs, fc, ac }` 里，11 套主题每套都有。**丢的不是能力，是入口。** 从来没有过调节控件，只有展示用的色片。

用户说"标题很多与内容不相关"——**属实，而且我上一轮就知道**。上一轮我把硬编码的体育稿词换成 `topicWords()` 从正文抽，方向对了，但模板骨架仍是上一稿的句式（「所有人都记住了X，没人记得别的」对纪念文章勉强能用，对其他题材就是废话）。**换模板，不只换词。**

用户说"下边的历史图片是什么玩意"——**是我造的，没有明确语义**。它显示的是"图库里还没插进正文的图"，但我把它叫"待用图片"、放在正文下方，语义是"随时可插入的备选"。问题是：用户已经要求配图默认配好，那这条就不该常驻。这是我的设计冗余。

## 2. 互相干扰与依赖（关键）

这批改动有几处会互相踩，必须排序。

### 依赖 1：P1-4 自动配图 依赖 P1-3 配图数量
先有"配几张"的配置，AI 才知道配几张。顺序：**P1-3 → P1-4**。

### 依赖 2：P1-4 自动配图 会让 P1-7 待用图片条 失去意义
自动配图后正文里已经有图，"图库里没用上的"就是纯冗余。
顺序：**P1-4 → P1-7**（先做完自动配图，再删这条）。

### 依赖 3：P0-6 编辑器合并 会改 .editor 尺寸，牵动 P0-4 字号预览
字号预览要在这个框里生效。顺序：**P0-6 → P0-4**。

### 冲突 4：P0-3 拉开样式差距 与 P0-4 字号可调 抢同一批 CSS
如果字号变成可调变量，主题的 `font-size` 就不能再写死，否则调节无效。
顺序：**P0-3 先重写主题（用变量占位）→ P0-4 注入变量值**。

### 冲突 5：P0-2 去卡片 与 P1-9 风格差异化 冲突
"卡片"作为一种风格被用户否了，但风格差异化要拉开差距。
处理：**删掉 `card` 主题，但保留"段落独立成块"这个结构手法**，改造成不叫卡片、观感不同的样式（如引用块式的分隔）。

### 冲突 6：P1-5 换标题模板 会让现有验收断言失效
`9c6 标题建议` 那批断言按旧模板写的。顺序：**先改模板，同步改断言**。

### 冲突 7：P0-7 改复制提示 与 P1-8 写作痕迹 同一类问题
都是"多余的解释性文字"。统一归到 P1-8 的规则里，一起改。

## 3. 实施顺序（每批独立可验收，互不干扰）

**第一批 · 排版内核（P0-1/2/3）**
只动 `layout.mjs`，不碰前端。可独立验收：11 套主题逐套量、确认无双栏无卡片、结构差异明显。

**第二批 · 排版控制（P0-4）**
动 `layout.mjs`（字号/颜色改变量）+ 前端加控件。依赖第一批。

**第三批 · 成稿页重构（P0-6 + P1-7）**
动 `app.js` + `app.css`。删阅读/编辑分离、删待用图片条。

**第四批 · 定题页重构（P0-5 + P1-3）**
动 `app.js`。拆排队/历史、加配图数量。

**第五批 · 热点页（P1-1 + P1-2 + P0-7）**
动 `app.js` + `app.css` + `server.mjs`（加预览接口）。

**第六批 · 内容生成流程（P1-4/5/6/8/9/2-4）**
只动 `AI操作手册.md` + `style-check.mjs` + `app.js` 标题模板。**这一批改的是 AI 的写作约束，不是界面。**

**第七批 · 定时刷新（P2-1）**
只动 `server.mjs`，独立。

## 5. Skill 可移植性的真实情况（用户直接问了，必须说实话）

用户问：别人从 GitHub 下载，任何 Agent 能不能用？

**诚实的答案：现在不能。** 三个硬依赖：

1. **必须有 Node 进程。** 热点抓取在 `server.mjs` 里，Agent 不启动这个服务就没有榜单。
2. **必须有 `markdown-it`。** 排版内核依赖它，`npm install` 才能跑。
3. **数据落在本地 `data/` 目录。** 换机器就没有历史稿和图库。

**能做到的最低改造（P2-3）：**
- 把热点抓取拆成独立 CLI：`node engine/hot-cli.mjs --json`，不依赖 server，Agent 可以直接调
- `package.json` 补 `engines` 与 scripts
- README 写清三步启动

**做不到的：** 任何 Agent 框架"即插即用"地拿到榜单。榜单本质是 HTTP 抓取 + HTML 解析，不同 Agent 的网络能力和运行时差异太大。这部分我只能给 CLI + 文档，不能吹成"任何 Agent 都能用"。

## 6. 版本号规则（用户明确要求写进底层）

**规则：每次改动打一个版本号，精确到秒。**

- 格式：`v{YYYYMMDD}-{HHMMSS}`
- 落地位置：`data/CHANGELOG.md`（人读）+ 每次验收结果追加一行
- 由脚本自动生成，不手写：`node engine/stamp.mjs "做了什么"`
- 验收测试里加一条断言：CHANGELOG 最后一条版本号时间不得早于最后一次代码修改时间

这样"改了哪些、什么时候改的"永远可追溯，不靠记忆。

## 7. 我会主动纠正的地方

用户有几处要求我判断需要调整，先说明，不擅自做：

1. **"去掉卡片形式"** — 我会删掉 `card` 主题，但保留段落分隔这个结构手法，换个不叫卡片的实现。不然风格差异化会少一种手法。
2. **"去掉待用图片条"** — 会删。但如果你之后想手动换图就没入口了。我建议改成"编辑时按图库键临时调出"，默认收起。
3. **"任何 Agent 都能用"** — 见第 5 节，我只能做到 CLI 可调用。
4. **"编辑/阅读不分开"** — 会合并。但要注意：合并后 Markdown 源码直接暴露给用户，非技术用户会看到 `![图注](文件名)` 这种东西。我会做成图片位置显示为缩略图卡片、源码在下方折叠。

以上四处如果你不同意，现在说，我按你的来。
