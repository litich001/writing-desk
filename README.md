# Write Work · 写作台

[![license](https://img.shields.io/badge/license-Apache--2.0-blue)](LICENSE)
[![node](https://img.shields.io/badge/node-%3E%3D20-green)](package.json)
[![local-first](https://img.shields.io/badge/data-local--first-orange)](#数据在哪)

**本地公众号写作工作台：选题 → 定题 → 成稿 → 配图 → 排版发布，全流程跑在你自己电脑上。**

AI 在你用的那个平台（Claude / GPT / 其他）里跑，这边只管**动手之前的准备和交稿之后的收尾**。
两边用纯文本文件交接，不绑任何模型、不调任何云 API。

> 如果你写公众号，每次都在「翻热点找选题、攒素材、调排版、复制粘贴」里转圈，
> 这个工具就是把那圈转不动的部分接过来：热点自动归并、写作任务自动生成、
> 事实清单自动核对、排版一键复制进公众号。人只干一件事——判断和表达。

作者：[李哲 Lizhe](https://www.lizhe.work) · 也在做 [Creator OS](https://www.lizhe.work) 内容工作流

**它在解决什么**：写公众号最耗精力的不是写，是那些转不动的琐事——
翻 15 个榜单找选题、把要求一遍遍交代给 AI、改完稿子再逐条核事实、
最后在公众号编辑器里一行行抠空格。写作台把这一圈接过来，
人只留判断和表达。

## 三步启动

三步，三分钟：

```bash
git clone https://github.com/litich001/writing-desk.git
cd writing-desk
npm install          # 只有两个依赖：markdown-it 和 markdown-it-footnote
npm run restart
```

浏览器打开 `http://127.0.0.1:8848`。

**要求**：Node.js ≥ 20（用到原生 `fetch`）。不需要数据库，不需要构建步骤，不需要联网也能写——联网只在抓热点和抓配图时用。

### 为什么是「本地服务」而不是「双击 HTML」

热点抓取需要服务端代理（浏览器直连第三方会被跨域挡），
排版预览和图片打包也需要。数据全部存在本地 `data/` 目录里，不上任何云。
你的稿子只躺在你的硬盘上。

## 五分钟走完一圈（怎么用）

这是**真实点击路径**，照着点就行。每一步都告诉你该看什么。

### 第 1 分钟 · 启动，打开就是热点页

```bash
git clone https://github.com/litich001/writing-desk.git
cd writing-desk
npm install
npm run restart
```

浏览器打开 `http://127.0.0.1:8848`。左侧四步导航，当前在第 1 步。

### 第 2 分钟 · 找一个能写的

热榜已经抓好了（同一条热搜跨平台已归并成一条）。
点任意一条 → 自动抓原文并出摘要，**不用你点「预览」**。

- 摘要能用 → 右上角「存」→ 自动跳到定题页，题框已填好
- 抓不到（头条/知乎/抖音这类）→ 工具会明说，并给「直接打开原页」

### 第 3 分钟 · 把活交给 AI

在定题页：选配图数量（默认 10 张）→ 提交。
任务出现在队列区 → **复制那段文字** → 粘进你的 AI 对话工具。

任务里已经带好了：题目、角度、配图数量、你的补充要求、当前事实清单状态。

### 第 4 分钟 · AI 交稿

AI 按 [`AI操作手册.md`](AI操作手册.md) 写完，把三样东西落进 `data/`：

| 文件 | 是什么 |
|---|---|
| `data/body.md` | 正文 |
| `data/titles.json` | 6 个候选标题 |
| `data/facts.json` | 可验证断言清单 |

页面**自动刷新**（不会打断你正在输入的字）。回到成稿页：

- 概要条上出现自检徽章 —— AI 味、标点、来源前缀、事实风险，红了当场看得见
- 右侧出现 **6 个候选标题，每条带字数** —— 点一下整条替换，不用复制粘贴

### 第 5 分钟 · 核对，然后发

1. 展开「事实清单」→ 高危项（精确小数/量级/百分比）逐条标已核
2. 图库展开 → 「推荐插入位置」面板点一下就插图
3. 发布页 → 左边点主题，右边即时出效果 → 点「复制图文（含图）」→ 去公众号粘贴

**一圈完了。** 全程没有一步是「打开另一个窗口」。

- **热点榜能单独用** —— 纯 CLI，喂给 Agent 做早报也行

### 四个页面全景

| 页面 | 一句话 |
|---|---|
| **热点** | 15 平台的公开热榜，跨平台归并去重，点条目直接看原文 |
| **定题** | 选题排队 + 历史稿，选配图数量，生成写作任务 |
| **成稿** | 一个文框直接改。图库、配图位置、事实核对、文风检测都在右边 |
| **发布** | 11 套排版主题、五项微调、一键复制（含图）到公众号 |

UI 有一份成文的设计规范（[`UI设计规范.md`](UI设计规范.md)）：
间距 8 档、字号 7 档、圆角 4 档，内容离屏幕边缘至少 16px。
看着顺眼不是调出来的，是量出来的——规范里写着每个数是怎么测到的。

## 它和别的东西有什么不一样

**1. AI 是外挂的，不是内置的。**

很多 AI 写作工具把模型焊死在里面，模型一升级工具就过时。
这里反过来：AI 只通过 `AI操作手册.md` 接活——任务从哪读、结果写到哪、硬规矩是什么。
你换什么模型都行，工具这边不用改一行。

**2. 检查是写在代码里的，不是写在文档里的。**

`验收测试.js` 里有 **800+ 条断言、80+ 个分组**，覆盖：

- 标题有没有信息量（数字 / 实体 / 动作 / 立场，四样缺一不可）
- 标题 12~22 字、是不是六种句式而不是同一句话换词
- 正文有没有来源前缀、AI 味高不高、九种文风各是什么分
- 配图能不能真显示（渲染出 `<img>` 还要 HTTP 200 取得到，不是写了语法就行）
- 图注写没写出处、图片和内容对不对得上
- CSS 有没有悬空变量（引用了但没声明 = 那条声明静默作废）
- 间距是不是只有一套阶梯、页面留白是不是只有一个出处
- 每次改动有没有打时间戳版本

判据的写法是**先写红再写绿**：新规则先让验收变红，修完再看它变绿。
反向验证用的都是真实产出过的坏标题，不是现编的——
现编的烂标题是照着判据反面造的，天然躲得开判据。

**3. 数据是纯文本，不是数据库。**

`data/` 里面全是 `.md` 和 `.json`，能直接看、直接备份、直接 `git diff`。
稿子丢了？`git log` 里全有。换电脑？拷走 `data/` 就行。

## 命令行：热点榜可以单独用

热点榜可以脱离写作台单独用，任何能执行 Node 命令的环境都能拿到数据。
写定时任务、喂给 Agent 做早报都行：

```bash
node engine/hot-cli.mjs                    # 人看的表格
node engine/hot-cli.mjs --json             # 结构化输出
node engine/hot-cli.mjs --json --flat --top 30   # 最适合喂给模型
node engine/hot-cli.mjs --only weibo        # 只看一个平台
node engine/hot-cli.mjs --force             # 忽略 4 小时缓存，强制重抓
node engine/hot-cli.mjs --stale             # 过期也返回，附 stale 标记
```

**退出码有意义**：0 = 至少一个源出了条目；1 = 全军覆没。
调用方可以据此决定要不要重试，不会把「抓取失败」误当成「今天没热点」。

**关于可移植性，说句实话**：不能吹「任何 Agent 即插即用」。
榜单本质是 HTTP 抓取 + HTML 解析，不同 Agent 的网络出口和反爬处境差别很大。
能做到的是给一个纯 CLI、不依赖 server、不依赖浏览器、退出码明确。
其中百度、微博、头条是纯 JSON 接口，最稳；依赖 HTML 解析的源会随对方改版失效。

筛选逻辑的完整说明见 **[docs/热点筛选原理.md](docs/热点筛选原理.md)**。

## 检查与自检：800+ 条断言守着

```bash
npm test                  # 全量对抗验收（验收测试.js，800+ 断言）
npm run test:layout       # 布局体检（16 项）
node engine/layout.mjs    # 排版内核自检
node engine/extract-test.mjs  # 网页正文抽取单测（45 项，离线）
node engine/style-test.mjs    # 九种文风的对抗验收
node engine/style-check-me.mjs sharp   # 查当前正文符合哪种文风
node engine/scan-garbled.mjs  # 乱码扫描
node engine/safe-test.mjs     # 文件名安全处理
node engine/hot.mjs           # 热点源逐个体检
node 回归基线.js              # 跑回归；加 --save 更新基线
```

**正文抽取为什么有离线单测**：真网站会反爬、会改版，
打真网站测出来的失败分不清是代码错了还是对方拦了。离线样本能精确定位是哪条规则写错了。
实网抽样验证另有一个脚本（`engine/probe-peek.mjs`），两件事分开看。

`engine/` 下面有 60 来个脚本，命名基本就是功能名：
`grab-img` 抓图、`place-img` 配图定位、`title-check` 标题配套、
`verify-facts` 事实核对、`body-check`/`line-check` 正文体检、
`css-dup` 重复选择器、`scan-old-colors` 旧配色残留……想加新检查，照着写一个就行。

## 数据在哪

全部在 `data/` 目录，纯文本，可以直接看、直接备份：

| 文件 | 内容 |
|---|---|
| `body.md` | 正文（你要发出去的那篇） |
| `project.json` | 项目设置：主题、字号、文风、配图数量 |
| `titles.json` | 6 个候选标题 |
| `facts.json` | 待核事实清单 |
| `materials.json` | 素材库 |
| `images.json` | 图片清单 |
| `versions.json` | 历史版本 |
| `topics.json` | 选题库 |
| `queue/` | 任务队列 |
| `CHANGELOG.md` | 每次改动的时间戳版本记录 |

> **注意**：`data/` 里默认带着作者自己的当前稿件（`body.md`、`project.json` 等）。
> fork 之后第一次用，建议先把 `data/body.md` 换成你自己的第一篇，
> `data/versions.json` 和 `CHANGELOG.md` 会如实记下这一切。

## AI 怎么接活

`AI操作手册.md` 是给 AI 看的 —— 任务从哪读、结果写到哪、硬规矩是什么。
改了写作规则记得同步更新那份手册，验收里有断言检查「手册和代码说的是同一件事」。

`engine/tasks.mjs` 负责生成写作任务，`engine/styles.mjs` 管九种文风的判据。
标题功能（`engine/title-mine.mjs` + 候选区）按这个逻辑工作：
通读全文 → 抽素材 → 起 6 个不同句式的标题 → 每个 12~22 字 → 每个带立场落点。

## 版本戳

每次改动都要打时间戳版本号（精确到秒），统一入口：

```bash
node engine/stamp.mjs "改了什么"
```

写入 `data/CHANGELOG.md`。验收测试里有一条断言专门检查它存在且格式正确 ——
所以「忘了打戳」会被验收当场抓住。

```

├── app.js / app.css    # 前端交互 + 全部样式（含设计令牌）
```

## 已知限制

- **热点抓不到就是抓不到**。豆瓣返回 403、部分平台要 JS 渲染，界面会明说哪个源不可用。
  不绕过反爬 —— 需要时手动去原站看。
- **网页原文预览**：JS 壳页面（今日头条、知乎、抖音）抓不到正文，会明说抓不到并给「直接打开原页」。
  这不是 bug，是这类站点的正文确实不在 HTML 里。
- **11 套排版主题共用一套骨架**，靠结构特征拉开差距（首行缩进 / 分段 / 左轴线 / 首字下沉 / 通栏大字引语…），
  不是靠换颜色。
- **浏览器探针**：`engine/ui-check.mjs` 会生成 `ui-probe.js` 做真实布局测量，
  那是本地调试用的，不入库。
